# WK6 사용성 테스트 반영 수정본 (WK6 Working Prototype — Usability Test Revised Version)

이동 중 독서/활동을 이어가고 기록하는 모바일 working prototype의 **사용성 테스트 반영 수정본**입니다. 재검증(재테스트) 목적으로 만들었습니다.

| 버전 | 위치 | 설명 |
|---|---|---|
| 기존 WK6 (Before) | [`experiments/claude`](../experiments/claude) | 사용성 테스트 당시 원본. **변경하지 않고 그대로 보존** |
| **WK6 Revised (After)** | `wk6-revised/` (이 폴더) | P01~P04 및 P03 파일럿 관찰을 반영한 수정본 |

위치·환승·탑승·도착 감지와 밀리의 서재 앱 실행은 **모두 시뮬레이션**입니다. 데이터는 해당 브라우저의 localStorage에만 저장되며 외부로 전송되지 않습니다. (수정본은 기존 버전과 다른 저장 키 `wk6-revised-…`를 사용해 서로 데이터가 섞이지 않습니다.)

## 실행

`index.html`을 브라우저로 열거나, 이 폴더에서 아래 명령을 실행합니다(빌드 불필요).

```bash
python3 -m http.server 8765
# http://localhost:8765/index.html
```

| 주소 옵션 | 설명 |
|---|---|
| `?reset=1` | 저장된 데이터를 지우고 처음부터 시작 |
| `?bare=1` | **참가자용 화면**: 연구자용 시뮬레이션 패널 없이 휴대폰 프레임만 표시 |
| `?speed=4` | 환승·도착 시간을 4배 빠르게 재생 |
| `?screen=home` | 지정한 화면으로 바로 열기 (`&profile=fresh`로 신규 사용자 상태) |

## 재검증 기본 시나리오 (데이터 변화: 120쪽 → 144쪽)

1. **T00** 회원가입 → 집 `세본동`, 회사 `강남역` (Figma After 값) → 책 읽기 → `데미안` · `120쪽` → 서비스 `밀리의 서재` → 계정 → 권한 → **홈**
   - 홈 "최근 진행 중인 활동"에 `데미안 · 전자책 읽기 · 120쪽부터 이어 읽기`, "자주 이용하는 경로"에 `세본동 → 강남역`
2. **T01** 오늘의 활동 시작하기 → 경로 → 활동 선택(데미안) → 이동 시작 → 지금 전자책 읽기 시작
3. **T02** 독서 중 환승 직전(연구자 패널 `환승 직전` 또는 자동 진행: Island가 `다음 역에서 환승해요` 배너로 바뀌고 아래에 `읽은 위치 저장하고 잠시 멈추기` 카드가 나타남) → 그 버튼 또는 펼친 Island의 ■ → `144` 입력 → 저장 → "144쪽에 저장했어요"
4. **T03** `다음 지하철에서 이어 읽기` → 탑승 대기 → 탑승 감지 알림 → "144쪽부터 이어 읽기" → `이어 읽기`
5. **T04** 목적지 도착 → 이동 마무리하기 → **오늘 이동을 마무리했어요!** → 기록 남기기 → 오늘의 기록(144쪽 자동 입력, 평점 1회, 사진 올리기) → 결과(`데미안 · 마지막 읽은 위치 144쪽`) → 홈으로 → (필요하면) 홈 하단 `캘린더` 탭
   - 활동을 중간에 끝내는 경우(`활동 그만하기`)도 같은 순서로 이어지고, 캘린더는 마무리 직후 자동으로 열리지 않습니다.

기존 사용자 로그인(로그인 화면의 로그인 버튼)은 `데미안 · 120쪽`이 복원된 홈으로 들어가므로 T01부터 바로 시작할 수 있습니다.

## 주요 변경 사항

관찰(P03 파일럿에서 실제 확인된 것)과 가설(코드에서 찾은 원인)을 구분해 수정했습니다. P03 한 명의 파일럿 관찰이므로 전체 사용자 행동으로 일반화하지 않았고, 수정 후 재검증이 필요합니다.

**데이터 일관성**
- 읽은 위치를 `state.currentReadingPage` **하나의 값**으로 관리합니다. 온보딩·읽기 화면·환승 기록·저장 완료·이어 읽기·오늘의 기록·결과·캘린더가 모두 같은 값을 읽고 씁니다. (`134p`, `158p` 등 고정값 제거. 메모는 `onTripNote`로 별도 관리)
- 집/회사는 온보딩에서 입력한 값(`세본동`, `강남역`)을 홈·경로·이동 시작·도착 화면이 그대로 사용합니다. 온보딩에서 등록하지 않은 지명이 홈/이동 화면에 임의로 나타나지 않습니다.
- 이동 시작/종료 시각, 총 이동 시간, 활동 시간을 별도 값으로 정의하고 한 곳(`core.js`의 trip 모델)에서 계산해 모든 화면이 공유합니다. (예: 08:34 → 09:30 · 이동 56분 · 활동 50분)
- 온보딩에서 입력한 책/위치가 홈 "최근 진행 중인 활동"에 바로 표시됩니다. 빈 상태는 등록된 활동이 정말 없을 때만 표시합니다.
- 홈의 `집 ↔ 회사`를 "자주 이용하는 경로 · 세본동 → 강남역"으로 바꿔 장소와 경로를 구분했습니다.

**이동 중 흐름**
- 환승 직전 "어디까지 읽었나요?"에 숫자 입력(`[ 144 ] 쪽`)과 "메모 남기기 · 선택"을 제공합니다.
- 저장 완료: "144쪽에 저장했어요", 다음 행동은 "다음 지하철에서 이어 읽기"로 변경했습니다.
- 탑승 대기: "다음 지하철 탑승을 기다리고 있어요 / 탑승이 감지되면 이어 읽을 수 있도록 알려드릴게요 / 지금은 아무것도 하지 않아도 괜찮아요". "여기서 그만할게요"는 "활동 그만하기"로 바꿨습니다.
- 재개 화면에 "144쪽부터 이어 읽기"와 `이어 읽기` 버튼을 보여 줍니다.
- 환승/도착 안내를 시간(`3분 후`) 대신 정거장 기준(`환승 3정거장 전 → 다음 역에서 환승해요 → 곧 환승해요`)으로 바꿨고, 환승 직전에 "환승 지점을 지났어요" 토스트가 함께 나오지 않도록 상태를 정리했습니다.
- Dynamic Island / Live Activity를 Figma "수정해야하는 프로토타입 화면들" 프레임의 실제 값으로 다시 맞췄습니다: 기본 `● 활동 중 … 12분 34초` pill(246×36), 환승 `환승 … 3정거장 전` pill, 환승 직전 배너(362×62) + `읽은 위치 저장하고 잠시 멈추기` 카드(362×163), 펼친 Live Activity(362×144, ■ 버튼 48px 원). 위치·폰트 크기·간격은 Figma 노드 값 그대로입니다. (■ 버튼에 붙였던 글자 라벨은 Figma에 없어 제거했고, 라벨이 있는 `읽은 위치 저장하고 잠시 멈추기` 카드가 그 역할을 합니다.)

**온보딩**
- 모든 온보딩 화면에서 Primary CTA(다음/건너뛰기/완료)를 화면 하단에 일관되게 두고, 상단에는 `이전`만 남겼습니다.
- 진행 표시를 Figma After대로 상단 한 줄에 정리했습니다: 뒤로가기 `<` · 길게 늘린 진행 바 · 오른쪽 끝에 숫자만(`n / 6`). 실제 단계가 6개라 `1 / 6 … 6 / 6`입니다. (기존에는 4칸 막대와 `3 / 4`가 실제 단계와 맞지 않았습니다.)
- 집/회사 추가: 주소 `선택` → `✓ 선택됨` → `집으로 추가하기`의 한 방향 흐름으로 정리했습니다.
- 회원가입: 닉네임·이메일·비밀번호·비밀번호 확인이 비어 있거나 형식이 맞지 않으면 `다음`이 비활성화되고 안내 문구를 보여 줍니다. (프로토타입 범위의 입력 검증이며 실제 계정 생성/서버 인증은 없습니다.)

**마무리**
- 활동 종료 후 흐름: `도착(또는 활동 그만하기) → 오늘 이동을 마무리했어요! → 오늘의 기록(이미지 올리기·만족도 상태 포함) → 결과 → 홈`. 마무리 화면의 주 버튼은 `기록 남기기`이고 `홈으로`를 누르면 기록은 저장한 채 홈으로 갑니다. 도착 화면은 Figma `[수정]목적지 도착`대로 `활동 진행 시간 / 최근 활동 시각(AM/PM) / 활동 재개(이어간 횟수)`를 보여 줍니다.
- 평점은 오늘의 기록에서 **한 번만** 묻습니다. 질문과 척도를 맞췄습니다: "오늘 이동시간을 원했던 방식에 가깝게 보냈나요?" `1 = 전혀 아니에요` … `5 = 매우 그래요`. 도착 화면의 "도움이 되었나요?" 질문은 제거했습니다.
- 오늘의 기록의 읽은 위치는 저장해 둔 값(144)으로 자동 입력되고, 필요하면 수정할 수 있습니다.
- 결과 화면에 `데미안 · 마지막 읽은 위치 144쪽`을 추가했습니다.

**연구자용 / 기타**
- 휴대폰 화면 안에 "환승 직전/탑승 감지/목적지 도착 시뮬레이션" 같은 검은 토스트가 뜨지 않도록 하고, 연구자 패널의 "최근 조작"에만 기록합니다. 참가자에게는 `?bare=1`로 패널 없이 보여 줍니다.
- 자산 로딩: 3.4MB였던 지도 PNG 2장과 Coupang 이미지를 JPEG로 압축(총 약 0.5MB)하고, 이미지·아이콘·폰트를 앱 시작 시 미리 불러옵니다. 하단 탭은 인라인 SVG 아이콘 + 라벨로 바꿔 로딩 지연이 없게 했습니다.
- 상태바 시각을 시뮬레이션 시계(이동 시작 08:34 기준)로 통일하고, 잠금 화면에서는 큰 시계만 표시합니다.

## 수정하지 않은 것

- T01(집→회사 이동 선택 → 활동 선택 → 데미안 → 전자책 읽기 시작) 플로우는 데이터 연결 외에는 그대로 두었습니다.
- 강의 듣기·뉴스·콘텐츠 추천 등 테스트하지 않은 기능은 추가하지 않았습니다.

## 알려진 한계

- 수정된 재검증용 Figma 프로토타입/User Flow 링크가 작업 시점에 공유되지 않아(공유된 Figma 파일은 수정 전 "Working Prototype 기준" 플로우), 요청서의 문구·구조 기준으로 구현했습니다. Figma 수정안과 문구·배치가 다르면 해당 화면만 조정이 필요합니다.
- 환승 역명은 가상 데이터를 만들지 않기 위해 "다음 역"/정거장 수로만 표시합니다.
- 동작 확인은 데스크톱 브라우저에서 했으며 실제 휴대폰·실제 이동 환경에서는 확인하지 못했습니다.
